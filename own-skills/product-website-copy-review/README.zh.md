# 产品网站文案审查

先找出真正影响理解、转化与信任的问题，再克制修改，同时保留产品事实和品牌语气。

## 什么时候用它

**审查整站文案**

我准备上线或改版产品网站，希望先检查影响产品理解、用户决策和信任的关键页面，再决定哪些内容值得修改。

**检查单个页面**

我的首页、落地页、功能页或价格页读起来不够清楚，或者模板化表达偏多。我想先看到主要问题，再获得少量必要的修改建议。

**检查全站一致性**

我需要确认多个页面中的功能名称、行动按钮、用户称呼、语气和产品承诺是否保持一致。

**不接**

它不用于翻译独立文本、检查实现代码，也不在文案质量未被要求时评审视觉设计。

## 它会产出什么

**它先审查再修改，已经有效的文案会保留原文。**

- **网站理解**：概括产品、核心用户、核心价值、主要行动按钮，以及本次覆盖的页面。
- **页面问题**：区分单页问题与全站问题，并标注影响与优先级。
- **全站汇总**：判断清晰度、信息层级、一致性、信任，以及是否存在模板化的 AI 或 SaaS 表达。
- **修改建议**：优先删除或微调，只有明显影响理解时才重写。
- **复核结论**：检查建议是否保持产品事实、品牌语气、页面长度和跨页一致性。
- **绝不会做**：不会虚构功能、数据、权限或承诺，也不会自行修改代码或发布网站。

## 前置条件与边界

**需要提供**

提供网站地址、一个或多个页面地址、页面截图、导出的文案，或页面结构与对应文本。受限页面需要在当前会话可访问，或者改为提供截图或文本。

**相邻任务分工**

| 任务 | 交给 |
|---|---|
| 修改网站视觉与界面 | **tranfu-website-design** |
| 搜索优化 | **seo** |
| 无障碍检查 | **accessibility** |

**边界**

- 整站审查优先覆盖影响理解、决策、转化、信任与产品体验的页面，不机械遍历全部页面。
- 单页快速检查仍然遵循「审查、汇总、修改」的顺序。
- 无法访问的页面会明确标记为未覆盖，不根据周边内容猜测。
