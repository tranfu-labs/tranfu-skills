# 多平台写作流程

把准备好的素材推进为共享大纲、两版母稿和完整平台改写。

## 什么时候用它

**大纲写作**

上游选题和素材已经批准后，我想生成 A/B 母稿和五个平台改写。

**优化大纲**

共享大纲还需要先调整并确认时，我想让流程停在批准点。

**完整写作**

我明确需要共享大纲加 A/B 五平台的完整写作阶段时使用它。

**不接**

普通单平台写作、小说、广告、调研、选题、只起标题、审校、配图、排版和发布都不交给它。

## 它会产出什么 / 你会看到什么

**它只交付本地结果，不负责平台发布，也不会替用户做额外授权。**

- **共享大纲**: 创建或优化所有正文共用的已批准大纲。
- **A/B 母稿**: 生成两份平台中立母稿，并隔离风格处理。
- **平台正文**: 生成公众号、小红书、知乎、微博和头条号版本。
- **绝不会做**: 不合并工作流阶段、不发布内容、不伪造缺失的用户确认。

## 前置条件 / 边界

**前置**

需要已有批准的选题和素材。未完成的调研或选题应先交给上游流程。

**相邻 skill 分工**

| 动作 | 交给 |
|---|---|
| 选择选题 | **content-topics** |
| 审校正文 | **proofread-content** |
| 生成标题 | **title-options** |

**不接的场景**

- 明确属于其他 skill 的请求，应交给对应 skill。
- 输入缺失或不可读取时，应停止并说明，不凭空补内容。
- 平台发布、账号登录、排期和发布后数据分析都不属于它。

**微妙边界**

- 完整内容生产流程可以把它当作 provider 调用，但它仍然只负责自己的契约产物。
- 独立使用时不应改动无关项目文件，只报告实际产出的文件或检查结果。
