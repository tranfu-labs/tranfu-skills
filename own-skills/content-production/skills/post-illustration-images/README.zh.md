# 多平台文章配图

生成可发布的文章配图包，并保持风格、后端检查和逐图质检稳定。

## 什么时候用它

**公众号配图**

公众号文章需要正文配图时，我想要统一注册风格和可交付文件。

**小红书组图**

小红书笔记或其他平台需要多张卡片时，我想让每张图独立规划、生成和检查。

**解释配图**

文章段落需要解释型视觉表达时，我想让画面与内容绑定，而不是套通用模板。

**不接**

纯摄影、人像或商品修图、写实品牌大片、图片里塞长文字，以及明确点名其他生图 skill 的请求都不交给它。

## 它会产出什么 / 你会看到什么

**它只交付本地结果，不负责平台发布，也不会替用户做额外授权。**

- **配图包**: 在用户项目输出目录写入提示词、原生图片、品牌或无品牌版本和清单。
- **后端预检**: 开始生产前先验证生图后端是否可用。
- **逐图质检**: 每张入选图都单独检查，已通过的像素不会被静默覆盖。
- **绝不会做**: 不合并工作流阶段、不发布内容、不伪造缺失的用户确认。

## 前置条件 / 边界

**前置**

需要可读取的文章或笔记内容、可用的生图后端和注册风格策略。产物写在用户项目输出目录，不写进 skill 目录。

**相邻 skill 分工**

| 动作 | 交给 |
|---|---|
| 生成微信封面 | **wechat-sketch-cover** |
| 压缩图片 | **compress-image** |
| 完整视觉阶段 | **content-production** |

**不接的场景**

- 明确属于其他 skill 的请求，应交给对应 skill。
- 输入缺失或不可读取时，应停止并说明，不凭空补内容。
- 平台发布、账号登录、排期和发布后数据分析都不属于它。

**微妙边界**

- 完整内容生产流程可以把它当作 provider 调用，但它仍然只负责自己的契约产物。
- 独立使用时不应改动无关项目文件，只报告实际产出的文件或检查结果。
