# 跨平台内容选题

选出一个有证据支撑的内容方向，并适配多个中文内容平台。

## 什么时候用它

**选择选题**

我有调研笔记或固定账号要更新，想选出一个今天能真正写成内容的主选题。

**素材提炼**

一批材料比较散时，我想把它们变成各平台可用的角度和主选题简纲。

**热点选题**

需要及时跟进 AI 或科技热点时，我想用公开信号和证据来决定写什么。

**不接**

完整写稿、只起标题、已有正文改写、单纯调研、内容日历、发布和数据分析都不交给它。

## 它会产出什么 / 你会看到什么

**它只交付本地结果，不负责平台发布，也不会替用户做额外授权。**

- **候选选题**: 生成有证据支撑的候选，并确定主选题。
- **平台角度**: 把主选题适配到公众号、小红书、知乎、微博和头条号语境。
- **简要大纲**: 交接给后续写作流程使用。
- **绝不会做**: 不合并工作流阶段、不发布内容、不伪造缺失的用户确认。

## 前置条件 / 边界

**前置**

需要提供本地调研材料、事实库，或允许使用公开信息。目标应是内容策划，不是发布。

**相邻 skill 分工**

| 动作 | 交给 |
|---|---|
| 收集素材 | **collect-sources** |
| 撰写正文 | **draft-content** |
| 生成标题 | **title-options** |

**不接的场景**

- 明确属于其他 skill 的请求，应交给对应 skill。
- 输入缺失或不可读取时，应停止并说明，不凭空补内容。
- 平台发布、账号登录、排期和发布后数据分析都不属于它。

**微妙边界**

- 完整内容生产流程可以把它当作 provider 调用，但它仍然只负责自己的契约产物。
- 独立使用时不应改动无关项目文件，只报告实际产出的文件或检查结果。
