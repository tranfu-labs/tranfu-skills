# 素材调研与核查

把科技写作想法先变成可追溯的素材包，再进入后续写作。

## 什么时候用它

**调研话题**

我准备写一个科技事件、AI 产品、开发工具或行业变化，想先拿到可靠的一手和二手素材。

**补充素材**

我已经有链接、Markdown、TXT 或 PDF，想让它提取有用信息，并补齐证据缺口。

**核查论点**

后续文章要依赖具体事实时，我想知道哪些论点证据充足，哪些还缺来源。

**不接**

非科技主题、没有写作目标的单点查询、成稿改写、只起标题、发布和发布后数据分析都不交给它。

## 它会产出什么 / 你会看到什么

**它只交付本地结果，不负责平台发布，也不会替用户做额外授权。**

- **调研记录**: 创建只追加的本地调研记录，保存来源、摘录和关键判断。
- **论点证据**: 提取论点，记录支持链接，并标出证据薄弱或未解决的部分。
- **交接材料**: 把材料交给选题、大纲或写作流程；它不会发布内容。
- **绝不会做**: 不合并工作流阶段、不发布内容、不伪造缺失的用户确认。

## 前置条件 / 边界

**前置**

需要联网，并能读取你提供的本地素材。请求应当服务于科技内容生产，而不是普通搜索。

**相邻 skill 分工**

| 动作 | 交给 |
|---|---|
| 选择平台选题 | **content-topics** |
| 撰写正文 | **draft-content** |
| 审校终稿 | **proofread-content** |

**不接的场景**

- 明确属于其他 skill 的请求，应交给对应 skill。
- 输入缺失或不可读取时，应停止并说明，不凭空补内容。
- 平台发布、账号登录、排期和发布后数据分析都不属于它。

**微妙边界**

- 完整内容生产流程可以把它当作 provider 调用，但它仍然只负责自己的契约产物。
- 独立使用时不应改动无关项目文件，只报告实际产出的文件或检查结果。
