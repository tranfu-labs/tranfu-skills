# 微信文章排版

把干净的 Markdown 文章转成已校验的微信正文片段和预览页。

## 什么时候用它

**排版 Markdown**

我有最终 Markdown，需要排成微信公众号正文，但不想改写内容。

**生成预览**

我需要带复制按钮的浏览器预览，并希望先校验干净片段。

**套用主题**

完整内容包走到排版阶段时，它负责公众号排版这一环。

**不接**

Word、PDF、TXT、富文本、其他主题、改写、普通网页、发布和微信接口操作都不交给它。

## 它会产出什么 / 你会看到什么

**它只交付本地结果，不负责平台发布，也不会替用户做额外授权。**

- **干净 HTML**: 写入已校验的微信正文片段。
- **预览页面**: 校验通过后生成便于复制的浏览器预览。
- **不改正文**: 保留 Markdown 原意，也不会发布到微信。
- **绝不会做**: 不合并工作流阶段、不发布内容、不伪造缺失的用户确认。

## 前置条件 / 边界

**前置**

需要提供可读取的 Markdown 文本或本地 .md 文件，并接受固定公众号主题。

**相邻 skill 分工**

| 动作 | 交给 |
|---|---|
| 审校正文 | **proofread-content** |
| 生成封面 | **wechat-sketch-cover** |
| 完整打包 | **content-production** |

**不接的场景**

- 明确属于其他 skill 的请求，应交给对应 skill。
- 输入缺失或不可读取时，应停止并说明，不凭空补内容。
- 平台发布、账号登录、排期和发布后数据分析都不属于它。

**微妙边界**

- 完整内容生产流程可以把它当作 provider 调用，但它仍然只负责自己的契约产物。
- 独立使用时不应改动无关项目文件，只报告实际产出的文件或检查结果。
