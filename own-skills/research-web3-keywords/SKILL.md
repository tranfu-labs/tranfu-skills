# Web3 关键词调研

把英文种子词或已有关键词主题转成可复核的搜索、竞品和收入证据，并给出是否进入候选项目的处理结论。默认研究全球 Web3 英文市场，不限公链和产品形态。

## When to use

处理关键词证据验证、竞品与收入调查、Lark 调研表填写和候选项目交接。它可以接收 `discover-web3-keyword-seeds` 的交接包，也可以从用户给出的现成关键词、竞品网址或 Search Console 查询开始。

## 前置输入

优先读取以下材料；缺少部分材料时，从已有输入继续，并明确未验证项。

- 种子词交接包、现成关键词主题、竞品网址或 Search Console 查询。
- 机会锚点及用户—任务—结果说明。
- 目标市场；默认全球英文，Semrush 首轮默认 US 数据库。
- 调研表和候选项目表入口；需要写入时确认当前身份有权限。
- 用户指定的排除范围或时间要求。

## 工具选择

按当前环境选择可用入口，不把某一种接入方式当作前置条件：

- **Semrush**：优先使用可调用的 Semrush 工具；没有接口时使用已登录网页。
- **Search Console**：使用已登录页面读取真实查询、页面、点击、曝光和排名。
- **Google 与 Google Trends**：核对搜索结果、广告、产品页、收费页和趋势性质。
- **公开资料**：查询项目收费、客户案例、协议收入、公司披露和可信第三方数据。
- **Lark**：优先使用 Base 能力按字段写入；不具备时输出可直接人工录入的结构化记录。

涉及已登录网页时，不读取密码、Cookie、会话存储或其他凭证。只记录调研需要的页面数据和公开链接。

## 工作流程

### 1. 按用户问题建立关键词主题

- 合并同义词、单复数和词序变化。
- 把指向同一用户任务和结果的词放进同一主题。
- 为每个主题选一个代表词，其余标记为长尾词、问题词、相关词或竞品词。
- 第一阶段只研究英文；验证成立后再反推中文。

### 2. 收集搜索证据

对每个主题记录：

| 来源 | 必查内容 |
|---|---|
| Semrush | 最近完整月搜索量、KD%、Intent、Trend、相关词和问题词 |
| Search Console | 真实查询、页面、点击、曝光、平均排名和页面缺口 |
| Google | 搜索结果类型、广告、直接产品、收费页和用户当前答案 |
| Google Trends | 最近 30 天上升、稳定、下降、波动或数据不足 |

遵守以下口径：

- 搜索量低不是单独淘汰理由，搜索量高也不能单独证明值得做。
- Search Console 的相似查询聚合为同一个用户问题。
- 拿不到最近完整月数据时留空，不用 12 个月均值替代。
- 每个数字记录工具、数据库、数据月份、查询日期和过滤条件。
- 收费页、收入、企业案例、监管要求和大量竞品只能证明商业问题可能成立，不能替代关键词搜索证据。

### 3. 分析对应项目和竞品

只把解决同一用户问题的产品、API、企业工具、付费报告、撮合服务或人工服务列为直接竞品。至少核对：

- 产品和收费页面。
- 主要功能、交付方式和目标客户。
- 用户反馈、常见问题和未满足需求。
- 收费对象、价格、计费方式和付费案例。
- 收入数据的来源、周期和对应产品。

项目名称相似但任务不同，或者收入来自其他业务时，标记“不匹配”。

### 4. 判断收入与付费证据

| 结论 | 判断方式 |
|---|---|
| 强 | 收入来自同一产品或服务，收费对象明确，数据可验证，并持续存在或增长 |
| 中 | 有明确价格、套餐、API 按量收费、付费客户或企业案例，但金额未公开 |
| 弱 | 只有广告、收费意向或项目自述，尚无真实付费证明 |
| 待核实 | 暂时查不到公开收入或付费资料，需要继续调查 |
| 不匹配 | 项目有收入但来自其他产品，或只有非收入指标 |

区分用户支付金额、平台总手续费、协议或公司实际收入，以及扣除成本后的利润。TVL、交易量、代币市值、融资、空投、返佣和补贴不直接算经营收入。

### 5. 得出处理结论

| 关键词证据 | 收入与付费证据 | 处理方式 |
|---|---|---|
| 强 | 强或中 | 标记“优先”，按主题创建“待评审”候选项目 |
| 强 | 弱或待核实 | 标记“进入验证”或“继续观察”，暂不创建候选项目 |
| 弱 | 强或中 | 保留代表词与证据，标记“继续观察”，转交竞品或收入项目调研 |
| 弱 | 弱或不匹配 | 记录停止原因，标记“淘汰” |

“关键词证据强”表示多个来源共同支持同一个真实用户问题和搜索目的，不等于达到固定搜索量门槛。

其中至少要有一项可复核的直接搜索数据：Semrush 最近完整月数据，或 Search Console 真实查询数据；同时真实搜索结果必须与同一用户问题和搜索目的吻合。两项都拿不到时，关键词证据最多标记为“待核实／弱”，即使收费和企业需求很强，也不能从关键词路径创建候选项目，应转交竞品或收入项目调研。

### 6. 填写关键词调研表

每条记录至少覆盖以下字段：

- **关键词本身**：关键词、关键词类型、用户问题、搜索目的、目标用户。
- **搜索证据**：数据月份、最近完整月搜索量、近 30 天热度变化、SEO 难度 KD%、Google Ads 商业信号。
- **竞品和收入**：对应项目或竞品、收入与付费验证、收入与付费证据。
- **原始依据**：数据来源及证据、调研附件、备注、调研人员。
- **最终处理**：关键词结论、关联候选项目。

无法确认的数字留空或标记“待核实”，不得补造。一个关键词主题可以包含多条关键词记录，但只创建一个候选项目。

### 7. 创建候选项目

只有“关键词证据强，并且收入与付费验证为强或中”的主题，才创建一条“待评审”候选项目。至少带入用户问题、关联关键词、直接竞品、竞品收费、收入证据、原始附件和待验证优势。

运营或 Agent 只能创建“待评审”，不能自行标记“通过”。最终立项必须另行执行项目立项规则，并证明至少两项可验证优势。

### 8. 判断停止

不设置关键词数量目标。当继续扩展已经无法产生新的用户问题、付费角色、使用场景、产品形态或直接竞品，新增结果基本只是同义表达时，停止扩展。

## 输出格式

即使无法直接写入 Lark，也按以下顺序交付：

1. 调研范围、工具状态和未验证边界。
2. 关键词主题及代表词。
3. 搜索证据表。
4. 对应项目、竞品和收入证据表。
5. 四分支结论及理由。
6. 可直接写入关键词调研表的字段记录。
7. 符合条件时，输出一条“待评审”候选项目记录；否则说明为什么不创建。
8. 原始链接、查询日期、数据月份和附件清单。

先报告可验证事实，再写判断。公开资料不足时明确写“待核实”，不要把推断写成已证实收入。
