# 文档内容处理

创建、改写、整理、审视和交付正式内容，让没有参与前期讨论的读者也能看懂重点、知道怎么做，并判断是否完成。

## 什么时候用它

- 创建或优化方案、制度、通知、报告、报价、操作说明、交接文档、JD 和客户材料。
- 把零散想法、会议记录、聊天内容、多个链接或现有文档整理成正式交付。
- 根据内容选择段落、表格、步骤、清单、时间线、截图或图示，改善文字过密的问题。
- 检查负责人、完成时间、前置条件、交付物、验收标准、链接和待确认事项是否清楚。

### 本 skill 独特价值

- 跨格式统一正式文档质量门禁
- 以陌生读者独立执行为验收
- 同时约束结构、术语、链接与回读

## 使用技巧

> 由 tranfu-publish 引导起草，帮助阅读者纵向上手；横向选择见上方“同类 Skill 对比”。

### 材料方案

- 提供原始资料、目标读者和用途
- 标明不可修改的事实与范围
- 有现成模板时一并提供

### 推荐用法

- 先整理内容，再调用平台写入能力
- Lark 写入同时搭配 `lark-doc`
- 最终交付前运行陌生读者检查

### 已知限制

- 不替代法律、财务等专业审核
- 缺失事实只标待确认，不代填
- 不负责单纯格式转换或线上发布

## 它会产出什么

- 先说结论和行动、适合目标读者阅读的正式内容。
- 根据内容选择段落、表格、步骤、清单、时间线、截图和图示，不为装饰堆格式。
- 清楚区分已确认事实、建议和待确认事项。
- 检查负责人、时间、输入、输出、依赖、风险和验收标准是否完整。
- 涉及第三方产品时补充并检查官方链接；真正写入平台或文件后完成回读或视觉检查。

## 前置条件与边界

提供原始材料、阅读对象、文档目的，以及不可修改的事实和表达。缺少的信息必须保留为待确认；不得补造负责人、日期、金额、责任或验收动作。本 Skill 负责内容质量，不负责平台权限和文件操作，因此修改 Lark、Word、PDF、表格或幻灯片时，需要同时使用对应能力。
