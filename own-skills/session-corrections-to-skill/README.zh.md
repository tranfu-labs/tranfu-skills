# session-corrections-to-skill 会话修正沉淀

把会话中的纠正变成可持久的 skill 知识，分两类存放。资格门判据统一是"存在一个被否定的既有行为"，否定者不同：用户纠正——用户否定 agent 的做法（偏好/约定类）；现实纠正——现实（报错、翻车）否定了原做法，且根因已查明、正确做法已在会话内验证（没找到就先去找，与用户确认后才入库）。范围指令、协作拍板的当次方案、一次性修改都进不了门；针对 agent 通用工作方式的修正直接打回——标注"不建议沉淀"，永不落 SKILL。

产出形态：用户纠正一行两列（场景 → 期望输出）；现实纠正一行三列（触发场景 → 正确做法 → 因果链链接），因果链复盘落 `references/<slug>.md`，SKILL 文件只放快速使用的经验、不放因果链本体。不新开章节、不复述既有内容、不借机重写。

归属时核对落点 skill 的职责范围：场景不在范围内就不放进去，没有任何 skill 覆盖则判定为"需新增 skill"（创建走创建流程，本 skill 不代建）。落盘前把每条「落点 SKILL → 拟追加行」发给用户确认，确认通过才写入文件。

## 什么时候用

- 一次会话里多次纠正了某个 skill 的行为，想让它记住
- 会话中踩了坑、查明了根因和正确做法，想把经验记进对应 skill

## 你会得到什么

- 用户纠正在正确的 SKILL 文件里追加一行「场景 → 期望输出」
- 现实纠正追加一行「触发场景 → 正确做法 → 因果链」，复盘落 reference 文档
- 一份对账单：纠正 → 落点 SKILL 路径 → 追加的行（现实纠正另附 reference 路径）
- 不沉淀的条目逐条打回并标注原因（一次性 / 通用工作方式等），不碰任何 SKILL 文件
- 单独的"需新增 skill"清单——没有 skill 覆盖的纠正不硬塞，留给创建流程
