# session-corrections-to-skill 会话修正沉淀

把会话中的纠正变成可持久的 skill 知识，分两类存放。资格门判据统一是"存在一个被否定的既有行为"，否定者不同：用户纠正——用户否定 agent 的做法（偏好/约定类）；现实纠正——现实（报错、翻车）否定了原做法，且根因已查明、正确做法已在会话内验证（没找到就先去找，与用户确认后才入库）。范围指令、协作拍板的当次方案、一次性修改都进不了门；针对 agent 通用工作方式的修正永不落 SKILL——单独列出标注待归档，本 skill 不代写 memory。

产出形态：用户纠正一行两列（场景 → 期望输出）；现实纠正一行三列（触发场景 → 正确做法 → 因果链链接），因果链复盘落 `references/<slug>.md`，SKILL 文件只放快速使用的经验、不放因果链本体。不新开章节、不复述既有内容、不借机重写。

## 什么时候用

- 一次会话里多次纠正了某个 skill 的行为，想让它记住
- 会话中踩了坑、查明了根因和正确做法，想把经验记进对应 skill
- 想把"该进 skill 的"和"只是我的通用偏好"干净分开

## 你会得到什么

- 用户纠正在正确的 SKILL 文件里追加一行「场景 → 期望输出」
- 现实纠正追加一行「触发场景 → 正确做法 → 因果链」，复盘落 reference 文档
- 一份对账单：纠正 → 落点 SKILL 路径 → 追加的行（现实纠正另附 reference 路径）
- 单独的"归 memory"清单——通用类修正不碰任何 SKILL 文件
