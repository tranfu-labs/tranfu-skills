# Excalidraw PRD 原型规范

把页面线框、产品规则和交互说明放在同一张 Excalidraw 画布中，用统一的视觉语法表达页面边界、产品标注和页面跳转。生成的 `.excalidraw` 文件可以继续编辑，适合用于产品讨论、需求评审和原型迭代。

## 使用案例

下面的 Todo 首页 PRD 由一句简短需求生成：

> 使用 $excalidraw-prd 绘制一个 Todo 应用首页的 PRD。

画板把页面线框、四组关键产品规则和验收口径放在同一个页面 frame 中，方便直接评审并继续补充细节。

![Todo 应用首页 PRD：页面线框、产品标注卡和验收口径](./assets/todo-home-prd-example.png)

## 什么时候使用

- 把已有 PRD 或产品说明转换成带标注的页面原型。
- 从零绘制一个或多个页面，并展示页面之间的跳转关系。
- 为现有画板补充模块职责、状态边界、业务规则和恢复路径。
- 修复页面 frame 包裹不完整、元素拥挤、标注含糊或跳转关系不清的问题。

如果需求本身尚未确定，应先明确目标用户、产品目标、功能范围和业务规则，再使用本 Skill 绘图。

## 开始前准备什么

输入越具体，第一版越接近可评审状态。建议至少提供：

- 页面范围与每个页面的目标；
- 核心操作和页面间的主要流程；
- 必须表达的状态、异常情况和业务规则；
- 希望重点标注的模块或验收要求；
- 桌面端、移动端或其他必要的界面约束。

不需要先把所有细节写成完整 PRD。缺少的信息可以在第一版之后继续补充，但关键规则仍需由产品负责人确认。

## 快速开始

最简调用：

> 使用 $excalidraw-prd 绘制一个 Todo 应用首页的 PRD。

信息更完整的调用：

> 使用 $excalidraw-prd 绘制一个桌面端 Todo 应用首页的 PRD。主区域展示今日任务，支持新增、筛选、排序、完成和撤销；请标注关键规则、异常状态和验收要求，并用箭头表达主要页面跳转。输出可继续编辑的 `.excalidraw` 文件。

生成后，在任意支持 `.excalidraw` 文件的编辑器中打开画板，检查内容并继续迭代。

## 画板会如何组织

- 每个页面都有一个明确的页面矩形边界。
- 页面矩形与相关产品标注共同放在带页面名称的外围 frame 中。
- 产品标注位于页面矩形之外、外围 frame 之内，避免遮挡界面内容。
- 标注卡使用语义色编号角标、同色边框、黑色标题和灰色描述。
- 页面跳转使用从真实操作点指向目标页面的实线箭头。
- 跨画布或首尾闭环的路径使用长回程箭头，避免再画一套重复流程图。

## 如何继续修改

可以直接说明观察到的问题，不必重新描述整个需求。例如：

> 使用 $excalidraw-prd 调整这个画板：拉开三个页面 frame 的间距，把筛选规则移到首页 frame 内，并让“新建任务”按钮的箭头直接指向新建页。

也可以只补充某一类信息：

> 使用 $excalidraw-prd 为当前页面补充空状态、保存失败和撤销操作的产品标注卡，不修改页面布局。

## 验收清单

- [ ] `.excalidraw` 文件可以正常打开并继续编辑。
- [ ] 每个页面 frame 完整包裹页面矩形和对应标注。
- [ ] 页面之间留有足够间距，没有文字重叠、内容截断或元素越界。
- [ ] 产品标注与页面模块的对应关系清楚，标题和描述易读。
- [ ] 跳转箭头从真实操作点出发，并明确指向目标页面。
- [ ] 核心流程、关键状态、异常情况和恢复路径均有表达。
- [ ] 画板内容没有擅自扩展或改变已经确认的产品需求。

## 能力边界

本 Skill 负责 Excalidraw PRD 画板的结构和表达规范。它不会替产品负责人决定需求，不负责实现前端代码，也不替代技术架构图或独立的业务流程图。
