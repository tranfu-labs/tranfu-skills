## 默认字体规范

字体家族继承项目配置。项目未指定字体时，使用目标平台稳定可用的系统字体栈，不由本 Skill 强制安装字体。

无项目规范时，根据页面类型选择一套标题密度。两套体系只允许 `font-weight: 600` 与 `font-weight: 400`：Display、H1–H6、页面标题、Section 标题、面板标题和卡片标题统一使用 `600`；正文、按钮、导航、标签、Caption、输入和值统一使用 `400`。

### 官网与 Landing Page

以一级模块标题 `36px` 为锚点向上、向下建立层级：

| 层级 | 桌面 ≥1024 | 平板 768–1023 | 移动 <768 | 字重 | 行高 | 字距 | 用途 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Display（可选） | 56px | 48px | 40px | 600 | 150% | -0.025em | 少量品牌宣言、活动标题 |
| H1 | 48px | 40px | 32px | 600 | 150% | -0.020em | 页面主标题；每页通常一个 |
| H2 / 模块标题 | 36px | 32px | 26px | 600 | 150% | -0.015em | 一级 Section 标题 |
| H3 | 28px | 24px | 22px | 600 | 150% | -0.010em | 子区块、重要面板标题 |
| H4 | 22px | 20px | 18px | 600 | 150% | 0 | 卡片组、表单分组标题 |
| H5 | 18px | 18px | 16px | 600 | 150% | 0 | 紧凑模块标题 |
| H6 | 16px | 16px | 14px | 600 | 150% | 0 | 最小标题层级 |

| 卡片/表单组标题 | 16px | 16px | 16px | 600 | 150% | 卡片、列表项、字段组 |

### 字体使用规则

- HTML 标题层级由文档结构决定，不由字号决定。
- 所有文字统一使用 150% 行高；CSS 写作 `line-height: 1.5`，设计标注按字号乘以 1.5 换算。
- 所有标题使用 `600`；正文与全部界面操作文字使用 `400`，不通过增加字重区分按钮优先级。
- H1–H3 默认不使用全大写；短标签可按项目语言规则处理。
- 连续正文建议控制在约 45–75 个字符的阅读宽度。
- 默认正文从 16px 开始；14px 仅用于次级正文，12px 仅用于 Caption、Badge 或非关键元信息。
- 承载关键操作、输入和值的文字不得使用 12px。
- 中文不使用人为增加的大字距；英文字母大写标签可沿用项目已有字距。
- 数字比较场景优先启用 tabular numbers，前提是字体支持。
- 小屏先重排布局，再缩小标题；不得把正文压缩到不可读。

## 默认间距规范

### 基础间距 Token

采用 `8px` 主网格，并保留 `4px` 作为唯一微间距。Token 后缀直接表示像素值，避免记忆抽象编号。页面布局、组件内边距和组件间距优先使用 8 的倍数；`4px` 只用于帮助文字、错误文字、图形细节等需要紧密关联的局部关系。

| Token | 数值 | 常见用途 |
| --- | ---: | --- |
| `space-0` | 0 | 无间距 |
| `space-4` | 4px | 帮助/错误文字、极紧凑图形关系 |
| `space-8` | 8px | 图标与文字、标签与控件 |
| `space-16` | 16px | 默认组件间距 |
| `space-24` | 24px | 卡片内容、字段组 |
| `space-32` | 32px | 模块内部主要分组 |
| `space-40` | 40px | 紧凑模块间距 |
| `space-48` | 48px | 产品内容区域、小型 Section |
| `space-56` | 56px | 移动端 Section |
| `space-64` | 64px | 标准模块间距 |
| `space-72` | 72px | 平板端宽松 Section |
| `space-80` | 80px | 大型模块间距 |
| `space-96` | 96px | 官网宽松 Section |

### 场景间距规范

基础 Token 只定义可用数值；场景 Token 负责说明用途和响应式取值。实现时让组件引用场景 Token，不直接散落基础数值。

#### 页面级间距

| 场景 Token | 用途 | 桌面 ≥1024 | 平板 768–1023 | 移动 <768 |
| --- | --- | ---: | ---: | ---: |
| `space-page-inline` | 页面左右安全边距 | `space-32` | `space-24` | `space-16` |
| `space-section-website` | 官网标准 Section 纵向间距 | `space-96` | `space-72` | `space-56` |
| `space-section-website-compact` | 官网紧凑 Section 纵向间距 | `space-64` | `space-56` | `space-40` |
| `space-section-product` | SaaS、Dashboard 与后台内容区域 | `space-64` | `space-48` | `space-40` |

#### 组件级间距

| 场景 Token | 用途 | 桌面 ≥1024 | 平板 768–1023 | 移动 <768 |
| --- | --- | ---: | ---: | ---: |
| `space-panel-padding` | 面板内边距 | `space-32` | `space-24` | `space-16` |
| `space-card-padding` | 卡片内边距 | `space-24` | `space-16` | `space-16` |
| `space-grid-gap` | 栅格间距 | `space-24` | `space-16` | `space-16` |
| `space-field-gap` | 表单字段间距 | `space-24` | `space-24` | `space-16` |
| `space-label-control` | 标签到控件 | `space-8` | `space-8` | `space-8` |
| `space-helper` | 字段到帮助/错误文字 | `space-4` | `space-4` | `space-4` |
| `space-icon-text` | 图标到文字 | `space-8` | `space-8` | `space-8` |

优先使用容器 `padding` 和布局 `gap` 表达关系。相邻可交互目标之间至少保留 `space-8`。除兼容既有实现外，不新增 `12px`、`20px` 等脱离主网格的间距，也不新增与基础 Token 只差 1–3px 的一次性值。

## 默认圆角规范

圆角采用 `8px` 递增体系，并提供直角选项。无项目规范时默认使用圆角；只有用户、品牌风格或组件结构明确要求直角时，才使用 `radius-none`。

### 基础圆角 Token

| Token | 数值 |
| --- | ---: |
| `radius-0` | 0 |
| `radius-8` | 8px |
| `radius-16` | 16px |
| `radius-24` | 24px |
| `radius-32` | 32px |

### 场景圆角规范

| 场景 Token | 对应值 | 用途 |
| --- | ---: | --- |
| `radius-none` | `radius-0` | 明确的直角风格、结构性边缘 |
| `radius-default` | `radius-8` | 默认按钮、输入框、菜单项、Tabs、Badge |
| `radius-card` | `radius-16` | 卡片、Popover、内容容器 |
| `radius-overlay` | `radius-24` | Dialog、Drawer、大面板 |
| `radius-display` | `radius-32` | Hero 展示容器、超大视觉表面 |
| `radius-full` | 几何计算 | 头像、圆形控件、明确胶囊 |

- 圆形元素使用 `50%`；胶囊圆角使用元素高度的一半，不使用 `999px` 作为基础 Token。
- 同一组件族使用同一级场景圆角。
- 无明确风格要求时，控件从 `radius-default` 开始，卡片从 `radius-card` 开始，不默认使用直角。
- 双层圆角存在可见且平行的内外轮廓时，必须使用同心圆角：`内层圆角 = max(外层圆角 − 两层间距, 0)`，不能让内外层直接使用相同数值。
- 常用组合：外层 24px、间距 8px、内层 16px；外层 32px、间距 8px、内层 24px；外层 24px、间距 16px、内层 8px。
- 只有彼此独立、轮廓不构成嵌套关系的同类组件，才使用相同的场景圆角 Token。
- 圆角不用于替代层级或分组。
- 交互状态不得改变圆角导致轮廓跳动。

## 默认控件尺寸

控件可见尺寸、交互热区和内部图标分开定义。可见高度使用 `32 / 40 / 48px` 阶梯；`44px` 只作为通用触控热区最低值，不作为标准控件高度。

### 可见控件高度

| Token | 高度 | 使用场景 |
| --- | ---: | --- |
| `control-compact` | 32px | 桌面高密度工具栏、紧凑筛选 |
| `control-default` | 40px | 默认桌面按钮、输入框、选择器、Tabs |
| `control-touch` | 48px | 移动端与高频触控操作 |

同一行中的按钮、输入框、选择器和其他控件必须使用同一尺寸 Token。主次操作通过位置、样式和文案区分，不通过控件高度区分。

### 交互热区

| Token | 最小尺寸 | 使用场景 |
| --- | ---: | --- |
| `target-pointer` | 32×32px | 桌面精确指针环境 |
| `target-touch-min` | 44×44px | 通用触控最低基线 |
| `target-touch` | 48×48px | 移动端高频操作推荐值 |

可见控件小于所需热区时，通过父容器或伪元素扩展命中区域，不得通过放大图标代替热区。相邻触控热区之间至少保留 `space-8`。

### 控件与图标匹配

| 控件高度 | 默认图标 | 常见用途 |
| ---: | ---: | --- |
| 32px | 16px | 紧凑控件 |
| 40px | 20px | 默认控件 |
| 48px | 24px | 触控控件 |
| 不适用 | 32px | 独立展示图标，不用于常规控件内部 |

- 可见图标尺寸与点击热区分开处理。
- 单行控件使用固定高度；Textarea 等多行控件使用最小高度并允许内容扩展。
- 使用 150% 文字行高时，必须确认文字行盒能够在对应控件高度中垂直居中且不被裁切。

## 默认深度规范

视觉阴影与页面堆叠顺序必须分开管理：`elevation-*` 只表达视觉悬浮强度，`layer-*` 只表达遮挡顺序。本节只定义阴影几何与堆叠关系，视觉属性沿用项目已有深度和主题实现。

### 阴影强度 Token

| Token | X | Y | 模糊 | 扩散 | 默认用途 |
| --- | ---: | ---: | ---: | ---: | --- |
| `elevation-0` | 0 | 0 | 0 | 0 | 页面、导航、默认卡片 |
| `elevation-1` | 0 | 1px | 2px | 0 | 轻微悬浮、可交互卡片 Hover |
| `elevation-2` | 0 | 4px | 12px | 0 | Menu、Tooltip、小型 Popover |
| `elevation-3` | 0 | 8px | 24px | -4px | 大型 Popover、浮动面板、Drawer 边缘 |
| `elevation-4` | 0 | 16px | 40px | -8px | Dialog、特殊高层浮窗 |

### 堆叠顺序 Token

以下数值只作为项目没有既有层级系统时的顶层默认值。组件内部优先建立局部 stacking context，不散落任意超大 `z-index`。

| Token | 默认值 | 用途 |
| --- | ---: | --- |
| `layer-base` | 0 | 常规页面内容 |
| `layer-sticky` | 10 | Sticky、Header、吸附工具栏 |
| `layer-dropdown` | 20 | Dropdown、Menu、Popover、Tooltip |
| `layer-overlay` | 30 | 遮罩、Drawer、全屏覆盖层 |
| `layer-modal` | 40 | Dialog、阻断式任务 |
| `layer-toast` | 50 | 全局通知与 Toast |

- 阴影只表达真实空间关系，不决定元素实际堆叠顺序。
- 默认页面、导航和卡片使用 `elevation-0`；仅在存在真实悬浮关系时增加阴影。
- Hover 最多提升一级阴影，并在离开后恢复；Selected、Loading 和 Pressed 不得通过改变外部尺寸表达状态。
- Dialog 通过 `layer-modal`、项目已有遮罩和 `elevation-4` 共同建立层级；Drawer 通过 `layer-overlay` 和朝页面一侧的边缘阴影建立层级。
- Focus 必须使用独立、持续可见的焦点样式，不能只依赖阴影。

## 交互状态

| 状态 | 默认行为 |
| --- | --- |
| `default` | 内容、边界和尺寸稳定可辨 |
| `hover` | 仅在支持 Hover 的指针环境提供临时反馈，不替代选中态 |
| `active / pressed` | 仅在按压期间提供即时反馈，释放后消失，组件尺寸不变 |
| `focus-visible` | 只表示键盘或等效输入方式的当前焦点，使用独立焦点环，不作为持久选中样式 |
| `selected / current` | 表示持续选择或当前位置；使用组件专属指示器和正确语义属性，默认不增加整圈外框或焦点环 |
| `expanded / open` | 视觉状态与可访问属性一致 |
| `checked` | 仅用于 Checkbox、Radio、Switch 等选择控件，通过控件自身标记明确选择 |
| `indeterminate` | 与 checked / unchecked 清楚区分 |
| `disabled` | 不可操作但内容可读，不响应 Hover / Active |
| `read-only` | 内容可读可选择，但不表现为可编辑 |

- `selected/current` 与 `focus-visible` 可以同时存在，但必须使用两种可区分的表现：选中指示持续保留，焦点环只跟随当前键盘焦点。
- 鼠标点击产生选中状态后，不得让焦点环持续冒充选中样式；实现时优先使用 `:focus-visible`，不把普通 `:focus` 直接设计成持久外框。
- 焦点环使用不改变组件盒模型的实现，不能推动布局或改变组件尺寸。
- 组件已有明确的选择控件、下划线、滑块、位置标记或状态图标时，不再添加重复的选中边框。
- Disabled 与 read-only 职责不同，不得混用。

## 内容加载与操作反馈状态

交互状态描述用户正在如何操作控件；本节描述内容加载阶段或任务执行结果。列表等数据内容通常经历 `loading → content / empty / error`，提交等操作通常经历 `default → loading → success / error`。

| 状态 | 默认行为 |
| --- | --- |
| `loading` | 明确正在处理并保持布局尺寸；按任务时长选择合适进度表现 |
| `empty` | 表示请求成功但没有内容；说明缺少什么，并在适用时提供下一步 |
| `error` | 表示加载或操作失败；说明原因或影响，并提供恢复路径 |
| `warning` | 说明风险及继续操作的后果 |
| `success` | 在触发操作或更新内容附近确认结果 |
| `info` | 提供补充信息，不遮蔽主要任务 |

只实现组件真实可能进入的状态，不机械补齐整张表。状态文案、图标、可访问属性和视觉表现必须一致；Empty 不得作为 Error 使用，Error 不得清除仍可恢复的用户输入。
