# 响应式布局与视口验证

本文件负责页面框架、Header、Section、内容容器、栅格、媒体、断点、重排和溢出。优先使用目标项目正式布局系统与断点；项目无规范时使用本文默认基线。

## 布局判断

先确定主要活动、必须同时可见的内容、可收起区域和项目支持的最小宽度。不能仅根据一张固定宽度截图推断整页行为。

## 默认断点

| 名称 | 宽度 | 用途 |
| --- | --- | --- |
| Mobile | 0–767px | 单列、触控优先、收起次级导航 |
| Tablet | 768–1023px | 两列上限、缩减辅助区域 |
| Desktop | 1024–1439px | 标准桌面布局 |
| Wide | ≥1440px | 宽工作区或增加外部留白 |

断点应在内容或交互开始失效的位置触发，而不是为设备名称机械匹配。项目已有断点时，不使用上表覆盖。

## 默认容器

| 容器 | 最大宽度 | 用途 |
| --- | ---: | --- |
| 阅读容器 | 720px | 长正文、文档、说明 |
| 标准内容容器 | 1200px | 表单、卡片、常规页面 |
| 宽内容容器 | 1440px | 数据看板、工作台、宽栅格 |
| Viewport Band | 100% | 全宽 Section、页面背景、视觉舞台 |

页面安全边距使用 `tokens.md` 的 `space-page-inline`。超宽屏优先增加外部留白或使用最大宽度，不无限拉宽正文行长。

## 容器角色

### 视口框架

用于全局导航、应用外壳、全宽 Section 和页面级区域。

- 跟随可用 viewport。
- 使用项目安全边距。
- 不用窄阅读容器限制全局导航。
- 固定子元素或媒体不得制造页面级横向溢出。

### 内容容器

用于阅读、表单、卡片、列表和扫描密集内容。

- 复用项目容器基础；无项目规范时使用上表。
- 保留响应式左右边距。
- 可收缩子项按需设置 `min-width: 0`。
- 不用内容容器错误限制全宽视觉或导航区域。

### 工作区

用于 Dashboard、Console、Editor、Canvas、Table 或 Split View。

- 保留主要工作区域。
- 在关键内容不可用前，先收起或移动次级区域。
- 可调整面板必须定义最小宽度。
- Resize、Collapse 和 Restore 控件需键盘与指针可达。

### 固定舞台

只用于确实需要固定画布、演示舞台或旧版兼容的场景。

- 放在响应式外壳内。
- 提供明确的溢出、缩放或小屏替代行为。
- 不把 Fixed Stage 当作普通页面默认外壳。

## Header 与导航

- 窄屏保留产品身份和至少一条可用导航路径。
- 次级导航按优先级收起、换行、滚动或移动。
- Menu 必须保持在 viewport 内，并可关闭。
- 当前导航项使用位置指示条、图标状态或项目已有 Current 标记；默认不使用焦点环或整圈外框作为持续选中样式。
- 键盘焦点与当前导航状态独立显示，`focus-visible` 只跟随正在聚焦的导航项。
- 默认 Header 高度：桌面 64px、移动 56px；项目已有值时沿用项目。

## 栅格与重复内容

- 项目无规范时，标准卡片最小宽度建议 280px，内容密集卡片建议 320px。
- 卡片宽度不足以保持信息层级前减少列数。
- 长内容不得意外撑大 Grid Track。
- 不直接复制设计稿固定宽度作为响应式规则。
- 栅格间距使用 `tokens.md` 的 `space-grid-gap`。

## Split View 与侧栏

- 明确主面板、可收起面板和收起后的去向。
- 小屏不保留所有桌面面板。
- 顺序型移动流程可将次面板转为路由、Drawer、Sheet 或堆叠 Section。
- 列表与详情切换时保留用户上下文。
- 隐藏或离屏内容不得困住键盘焦点。
- 无项目规范时，固定侧栏建议 240–320px，可调整面板最小宽度建议 280px。

## 表单与操作

- 多列表单在标签和控件拥挤前减少列数，重排后保留主要操作的位置关系。
- 视觉顺序变化时保持合理键盘和阅读顺序。
- 固定操作栏不得遮挡焦点字段或移动键盘。
- 校验和恢复路径靠近对应控件。

## 表格与高密度数据

根据用户比较任务选择：

- 横向滚动：保留列关系；
- 列优先级：隐藏次级信息；
- 行展开：查看详情；
- 列表/卡片转换：以单项浏览为主；
- 详情页：复杂记录。

不强制所有表格使用同一种移动模式。关键标识、状态和操作必须可访问。

## 媒体

- 需要完整 UI 或图表上下文时使用 `contain`。
- 已知安全裁切规则时才使用 `cover`。
- 并排媒体与文案过窄时重新构图。
- Loading 占位保持尺寸稳定。

## 溢出与韧性

必须测试：

- 长单词、URL、文件名、账号名和本地化文案；
- 大数字、日期、状态标签和动态计数；
- Empty、Loading、Error 和最大内容状态；
- 浏览器缩放与放大文字；
- Viewport 边缘的 Sticky / Fixed 区域；
- Menu、Popover、Tooltip、Dialog 和 Drawer；
- 嵌套滚动容器与键盘焦点。

根据内容选择换行、可查看全文的截断、重排、减少列或明确滚动。不能只为截图整洁而隐藏有意义内容。

## 视口验证

页面外壳、导航、栅格或响应式变更，无项目测试矩阵时默认检查：

- 1440px：标准宽桌面；
- 1280px：常见桌面/笔记本；
- 1024px：紧凑桌面；
- 768px：平板边界；
- 375px：小型移动端。

窄范围组件改动至少检查一个桌面宽度和一个移动宽度。只记录实际观察的视口。

```yaml
- width: <像素>
  status: passed|failed|not_run|not_applicable
  reason: <原因或 null>
  evidence: <截图、观察或静态证据>
```

只有检查真实渲染后才能标记 `passed`。静态代码推理可以支持发现，但不能证明视觉通过。
