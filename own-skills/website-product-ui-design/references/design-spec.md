# 网站与产品 UI 设计原则

本文件只保留会改变视觉决策的通用原则。权威来源顺序、冲突处理和输出格式以 `SKILL.md` 为准；具体数值由 `tokens.md` 负责。

## 先判断页面任务

开始设计或评审前，先确定页面主要属于哪一种任务：

| 页面任务 | 优先保证 | 避免 |
| --- | --- | --- |
| 官网、Landing Page | 叙事顺序、价值表达、真实产品证据 | 用装饰视觉替代产品信息 |
| SaaS、Dashboard、后台 | 扫描效率、操作路径、状态与数据密度 | 直接套用官网的大标题和宽松间距 |
| 表单、配置、向导 | 输入顺序、校验恢复、主要行动 | 为视觉对称打乱任务顺序 |
| 工作台、编辑器、Split View | 主工作区尺寸、上下文保持、面板恢复 | 在小屏强行保留所有桌面面板 |
| 文档、知识库、长内容 | 阅读宽度、目录和内容连续性 | 用卡片切碎连续正文 |

页面同时承担多种任务时，以用户当前主要活动决定主布局，其余内容作为次级区域处理。

## 视觉决策原则

1. **真实产品证据优先**：解释产品能力时，优先展示真实界面、工作流、数据或可信 Mockup；装饰视觉不能替代关键信息。
2. **结构先于表面效果**：优先用分组、间距、对齐和排版建立层级；只有真实边界存在时才增加卡片、描边或阴影。
3. **信息密度服从任务**：操作界面可紧凑，营销页面可宽松；不能用任意大留白制造层级。
4. **视觉层级不等于 HTML 层级**：字号按任务体系选择，H1–H6 由文档结构和可访问性决定。
5. **响应式优先重排**：空间不足时调整导航、列数、信息优先级和媒体关系，不把桌面构图整体缩小。
6. **状态解释系统行为**：Loading、Empty、Error、Selected、Disabled 和 read-only 必须与真实系统状态一致，不能互相代替。

## 三层视觉模型

- **基础层**：页面框架、主要区域和全局导航。
- **内容层**：Section、面板、列表、表单、表格和重复内容项。
- **行动与状态层**：主操作、当前位置、系统反馈和临时浮层。

该模型只描述视觉职责，不要求增加 DOM 或卡片嵌套。间距、标题或列表结构足以表达关系时，不再增加表面层。

## 品牌与项目资源

- 只使用用户提供、目标项目已有或权利方正式发布的资源。
- Logo 必须保持项目规定的比例、组合、留白和批准版本。
- 未经明确授权，不重绘、近似替代、改色、裁切、拉伸或给 Logo 添加效果。
- Logo 与第三方服务标志不能替代功能图标。
- 缺少必需资源或使用规则时报告缺口，不自行虚构。

## 评审重点

只报告能定位到代码、设计稿、截图或真实渲染状态的发现，重点检查：

- 页面任务与信息密度是否匹配；
- 是否误用卡片、描边或阴影制造层级；
- 视觉标题与 HTML 语义是否被混为一谈；
- 选中、焦点、加载、空、错误和只读状态是否职责清楚；
- 小屏是否完成重排，并保留主要任务和恢复路径；
- Logo、产品截图和第三方标志是否来自可信资源。
