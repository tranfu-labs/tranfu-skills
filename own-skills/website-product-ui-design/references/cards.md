# 组件与界面模式

本文件只定义组件之间不同的结构与状态决策。共享字号、间距、圆角、控件高度、热区和深度使用 `tokens.md`；只属于单个组件的尺寸在本文定义一次。

## 通用组件规则

- 同类控件复用同一组件、尺寸角色和状态模型。
- Hover、Focus、Loading、校验和内容变化不得改变组件外部尺寸。
- 没有独立内容或交互边界时，不用卡片嵌套制造层级。

## 容器、卡片与面板

独立重复项或可操作单元使用卡片；大型内容区域、工作区、分组表单或产品演示使用面板。

- 交互卡片必须明确整卡点击与内部按钮的边界，避免竞争点击目标。
- 可选择卡片使用 Check、Radio 或固定位置的选择标记；除非项目既有规范明确要求，否则不为整个选中卡片增加外框。

默认卡片使用 `tokens.md` 的 `radius-card`、卡片内边距、栅格间距和 `elevation-0`；项目已有卡片组件时以项目为准。只有存在真实悬浮关系时才增加阴影，可交互卡片 Hover 最多提升到 `elevation-1`。

## 按钮

### 层级

- 同一区域只保留一个主行动。
- 次按钮承载替代操作、取消、返回或低优先级任务。
- 文本按钮或 Ghost 按钮用于密集场景中的轻量操作。
- 危险或不可逆操作通过明确文案、位置、确认和项目状态样式区分。

### 尺寸

- 紧凑按钮使用 `control-compact`，仅用于桌面高密度工具栏。
- 默认按钮使用 `control-default`；移动端与高频触控按钮使用 `control-touch`。
- 移动端与触控环境点击热区至少使用 `target-touch-min`，高频操作优先使用 `target-touch`。
- 水平内边距通常使用 `space-16`；紧凑按钮使用 `space-8`，触控或宽松按钮使用 `space-24`。
- 主按钮、次按钮和危险按钮可以使用相同高度，不能只通过尺寸表达操作优先级。

### 行为

- 覆盖 `hover`、`active`、`focus-visible`、`disabled`；只有异步操作才增加 `loading`。
- Loading 保持按钮尺寸，并在适用时防止重复提交。
- Disabled 与 read-only 明确区分，且不应看起来仍可点击。
- 纯图标按钮必须有 accessible name。
- 按钮组响应式换行后仍保持合理操作顺序。

## Tabs 与分段控件

- Tabs 用于切换同一上下文中的同级内容，不用于连续步骤或无关页面导航。
- 当前项必须具有程序化 selected/current 语义。Tabs 默认使用下划线或位置指示器，分段控件默认使用内部滑块；除非项目既有规范明确要求，否则不为整个选中项增加外框。
- `focus-visible` 只标记当前键盘焦点项，与持续存在的选中指示器分开显示。
- 键盘交互应符合所选 Tab 模式。
- 选项过多时允许滚动、换行、选择器或替代导航，不压缩到不可读。
- 切换选中态不得推动周围布局。
- 默认使用 `control-default`；紧凑桌面场景使用 `control-compact`，移动高频场景使用 `control-touch`。

## 标签与 Badge

- 用于简短分类、状态、数量、版本或元信息。
- 默认字号使用标签 S；需要更强可读性时使用标签 M。
- 默认高度 24px；紧凑元信息可用 20px，重要状态可用 28–32px。
- 水平内边距通常使用 `space-8`，文字较长时使用 `space-16`。
- 可点击 Badge 的可见尺寸可以保持不变，但完整交互热区必须满足对应的 Pointer 或 Touch Token。
- 交互标签按需具备 Hover、Focus、Selected 和移除状态。
- 可选择标签使用内部 Check、Pressed 语义或项目已有标记，不把焦点环作为持续选中样式。
- 状态标签使用明确文字和项目语义，不能只依赖颜色。

## 表单、搜索与筛选

### 结构

- 每个控件提供可见 Label 或等效 accessible name。
- Label 使用标签 M；输入值使用正文；帮助和错误文字使用标签 S 或次级正文。
- Label 到控件使用 `space-label-control`；控件到帮助/错误文字使用 `space-helper`；字段之间使用 `space-field-gap`。
- 输入框、选择器默认使用 `control-default`；紧凑桌面工具使用 `control-compact`，移动端与高频触控场景使用 `control-touch`。
- 同一行的输入框、选择器和按钮必须使用相同的控件高度 Token。
- 可恢复错误应保留已输入值和用户上下文。

### 状态与恢复

- 校验信息以程序方式关联字段或字段组。
- 校验不能只依赖颜色。
- Loading 与 Success 不得意外改变表单尺寸。
- 搜索与筛选提供清除或重置路径。
- 筛选空结果需要区分“没有数据”和“没有匹配结果”。

### 响应式

- 多列表单在控件拥挤前改为单列或更少列。
- Label、值、帮助文字和操作不得依赖横向滚动阅读。
- 复杂筛选在窄屏可转为菜单、Popover、Drawer 或独立视图。

## 列表

- 列表正文使用次级正文或正文；产品界面的列表项标题使用“卡片/表单组标题”，官网列表按所在 Section 的语义标题层级取值。操作与状态标签使用 400。
- 关键行内操作不得只在 Hover 时出现。
- 选中行需要程序化状态，并使用 Checkbox、Radio、行首标记或固定状态图标表达；默认不为整行增加焦点外框。
- 只有存在选中项时显示批量操作，并贴近列表上下文。
- 默认桌面列表行不低于 `control-default`，触控列表行不低于 `control-touch`；高密度桌面列表可使用 `control-compact`，但必须保持文字和操作可用。

## 表格

- 表头使用标签 S 或标签 M，表格内容使用次级正文或正文。
- 按需覆盖 Loading、Empty、Error、Selected 和 Saved。
- 表格选中行沿用列表选择规则；键盘焦点只标记当前可操作单元，不冒充整行选中状态。
- 行操作必须键盘可达，不依赖 Hover 才能访问。

## 分页与结果导航

- 通过语义和固定的当前页标记清楚表达位置；焦点环只跟随键盘焦点，不作为当前页的持久样式。
- 小屏减少页码密度，但保留当前位置和前后导航。
- 结果加载时保持导航区域稳定。
- 默认分页控件使用 `control-default`，高密度桌面可使用 `control-compact`；触控环境使用 `control-touch`。

## Menu、Popover 与 Tooltip

- 关闭后焦点返回触发器或合理后续位置。
- 菜单项默认使用 `control-default`；触控环境使用 `control-touch`。热区必须覆盖整个菜单项，而不只是文字。
- Tooltip 只承载短补充说明，不承载主要指引或复杂交互。
- 浮层不得被视口或滚动容器裁切。
- Popover 默认使用 `radius-card` 与 `elevation-2`；Dialog 和 Drawer 默认使用 `radius-overlay`。Dialog 使用 `layer-modal` 与 `elevation-4`，Drawer 使用 `layer-overlay` 与朝页面一侧的 `elevation-3` 边缘阴影。

## Dialog 与 Drawer

- Dialog 用于聚焦决策、确认或短任务。
- Drawer 用于上下文详情、筛选、导航或保留页面上下文的次级流程。
- 关键流程不能只依赖点击外部关闭。
- 小屏应重排或扩展，不压缩内容。
- Dialog 桌面常用宽度 480–640px；复杂内容应进入专门页面，不无限放大弹窗。

## Toast 与短暂反馈

- Toast 用于简短结果或异步反馈，不承载完成任务必需的信息。
- 不遮挡主操作或模态按钮。
- 重要状态变化还应在持久内容或可访问播报中出现。
- 默认宽度不超过 400px；移动端使用视口安全边距内的可用宽度。

## 内容加载与操作反馈

### 空状态

- 区分“没有数据”和“没有匹配结果”，并提供与原因对应的创建、导入、清除筛选或更换查询入口。

### 加载状态

- 保持尺寸；按预计时长选择进度、Skeleton、Spinner 或后台处理，长操作按需提供取消、重试或安全离开路径。

### 错误状态

- 在受影响任务附近说明失败内容、影响和恢复路径；多个错误提供摘要或逐项导航。

### 成功状态

- 在触发操作或更新结果附近确认；内容更新已足够表达成功时，不额外打断用户。

### 警告与信息状态

- Warning 用于说明可以继续但存在的风险、影响和后果，不冒充 Error。
- Info 用于中性补充说明，不阻断任务，也不遮蔽主要操作。
- 只实现组件真实可能进入的状态，不为满足状态清单增加无意义界面。
