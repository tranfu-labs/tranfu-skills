# 占比热力图默认判断

在动手画“热力图”前，先判断问题真正要看面积占比，还是固定格子的颜色强弱。

## 什么时候用它

**营收占比图**

我说“做个热力图”，同时提到占比、份额、分布、谁占大头、谁多谁少，想让模型先判断方块面积是不是应该表达业务含义。

**日历热力图**

我在做按天、按小时、行列矩阵这类固定格子图，想避免模型一看到“热力图”就误套 Treemap，把原本固定的格子改成大小不一的方块。

**口径切换**

同一份数据有累计、近 24 小时、近一周、近一月、近一年等多个统计口径时，我想要清楚的切换控件，而不是面积代表一个口径、颜色又代表另一个口径。

**不接**

不是用来在柱状图、饼图、折线图之间做初选，也不是用来写 Treemap 算法、CSS 布局或验证脚本。

## 它会产出什么 / 你会看到什么

**最关键的产出，是在实现前先给出 Treemap / 固定网格的编码判断。**

- **编码选择**：判断“大小”本身有没有业务含义；有就考虑 Treemap，没有就保持固定格子。
- **Treemap 默认**：当问题是“谁占整体多少份额”时，用面积真实表达占比，颜色只能做辅助维度。
- **网格默认**：当格子位置本身有固定含义，比如日期、小时、矩阵行列，格子大小保持一致，只用颜色表达强弱。
- **口径切换**：多个时间窗口或统计口径并存时，用 Tab 或下拉切换；切换后面积和颜色同时按同一个口径重算。
- **自检问题**：只看方块面积，能不能看出谁占比更高？如果不能，就回头重判编码方式。
- **绝不会做**：替你实现布局算法、坐标计算、CSS、配色、数据抓取或验证脚本。

## 前置条件 / 边界

**前置**

需要一段图表需求，里面至少能看出“热力图”请求和是否存在占比、份额、分布、谁占大头这类语义。

**相邻工作分工**

- 图表大类选择，比如柱状图、折线图、饼图之间怎么选，交给模型按常规可视化经验判断。
- Treemap 的布局算法、坐标、CSS 和测试，交给实现阶段处理。
- 配色和色阶只是视觉表达问题，不等同于面积与颜色该承载什么含义。

**不接的场景**

- 没有占比或份额语义的普通热力图。
- 日历热力图、相关系数矩阵、固定行列网格这类格子大小不应变化的场景。
- “分布”指沿某个维度的疏密变化，而不是“各部分占整体多少”的场景。

**微妙边界**

如果语义模糊，先问一句：“这个热力图是看各项占整体的比例，还是看每一项自己的强弱或活跃度？”前者走 Treemap，后者通常不是本判断要处理的占比热力图。
